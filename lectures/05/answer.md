## 宿題

- 取り組んだレベル：基礎
- やったこと（変更したファイル・設定・処理、または設計した取得方法）：`app/config.py` の `RAG_TOP_K`（通常のベクトル検索で取得する件数）を初期値の `5` から `1`（最小）と `10`（増加）の2パターンに変更し、取得件数の増減による挙動とコストの変化を比較した。
- 比較した質問と、固定した条件（モデル・対象資料など）：
  - 質問：「第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？」
  - 固定条件：モデルは `gemini-3.5-flash-lite`、対象資料は第1〜3回の本講義214ページ（`index.sqlite3`）、実行オプションは `--trace` で統一。
- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：
  - **変更前（初期値：`RAG_TOP_K = 5`）**
    - ツールの呼ばれ方：`search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'})` を1回呼び出し、上位5ページを取得。
    - 回答・引用根拠：LoRA（元の重み固定・小さな行列A・Bの差分を学習）とQLoRA（4bit圧縮を追加）を正確に回答。引用は「第2回・PDF p.51, p.52」。

  - **変更後①（`RAG_TOP_K = 1` に削減）**
    - ツールの呼ばれ方：`search_materials({'query': 'LoRA 固定 学習 QLoRA 加える'})` を1回呼び出し、最上位1ページ（`lec02-main-p052`）のみを取得。
    - 回答・引用根拠：LoRA（元の重みWを固定・行列A・Bの差分を学習）とQLoRA（4bit圧縮を追加）を過不足なく正確に回答。引用は「第2回・PDF p.52」のみに絞られた。

  - **分かったこと・改善点**：`RAG_TOP_K` を `1` → `5` → `10` と増やすにつれて、入力トークン数は `1,191` → `3,026` → `5,189`、推定費用は `$0.000762` → `$0.001463` → `$0.002009` とほぼ比例して増加した。今回の質問は1位にヒットしたp.52だけで答えが完結するため、`RAG_TOP_K = 1` に絞ることで `10` 件時と比べて入力トークンを約77%削減しつつ同等の回答精度を得られた。
  - **残る制約**：`RAG_TOP_K = 1` では複数ページにまたがる質問で根拠を取りこぼすリスクがあり、逆に `10` に増やすと無関係な周辺ページが増えてコストが嵩むため、単一の固定値ですべての質問に最適化することは難しい。
- 気づき・疑問：取得件数を10件に増やしてもモデル自身は不要な9ページを無視してp.52だけを根拠に選べていたが、APIの入力トークン課金は渡した全ページ分に対して発生する。検索精度とコストのバランスを取るには、質問の性質に応じて取得件数を調整する設計が重要だと実感した。
